# Сборщик Amestat

Локальная половина проекта: сайт на GitHub Pages только показывает, а цифры в базу приносит
этот пакет — он живёт на домашнем компьютере владельца, водит установленный браузер по
профилям креаторов и пишет снимки в Supabase ключом `service_role`.

Почему не в облаке: TikTok отдаёт список видео только настоящему браузеру с настоящего
домашнего адреса. Поэтому обход — дома, а сайт остаётся статикой без сервера.

## Что он делает

| Повод | Метка обхода | Откуда |
|---|---|---|
| 10:00, 13:00, 17:00 по местному времени | `schedule` | часы резидента |
| компьютер спал и слот прошёл без обхода | `catchup` | догон при старте `watch.mjs` |
| кнопка «Обновить» на сайте | `manual` | строка в `sync_requests` (Realtime + опрос раз в минуту) |
| руками из командной строки | `manual` | `npm run run` |
| через час после неудачного `schedule`/`catchup` | `retry` | таймер резидента, только неудавшиеся креаторы |

Каждый обход — строка в `sync_runs` (начало, конец, `ok`, счётчики, построчный лог).
По каждому креатору — снимок профиля в `creator_snaps`, список видео в `videos`
(upsert по `id`) и снимок счётчиков в `video_snaps`. Один `taken_at` на креатора: разности
за срок считаются между снимками, и они должны быть сделаны «в один миг». Следом по свежим
видео снимаются тексты комментариев в `video_comments` — про этот шаг ниже, в «Комментариях».

Поля `videos.first_seen_at` и `videos.ours` сборщик не трогает вовсе — первое ставит база,
второе триггер и владелец на сайте. В `creators` он пишет только `last_synced_at`,
`sync_error` и аватар площадки — и тот лишь если владелец не загрузил свой
(`creators.avatar_custom = false`); имя и описание креатора — владельца, ник и подпись
площадки их не перебивают. У Instagram вместо адреса площадки в базу идёт адрес нашего
хранилища — почему, ниже, в «Картинки Instagram».

## Глубина: всё или неделя

У просьбы (`sync_requests.depth`) и у обхода (`sync_runs.depth`) два значения:

- `all` — весь список видео креатора, как было всегда;
- `week` — только видео, опубликованные за последние 7 дней.

Неделя — не фильтр в конце, а ранний выход: списки обеих площадок идут от новых к старым,
поэтому обход перестаёт листать, как только в пришедшей пачке оказалось видео старше недели,
и уже потом отсекает старых соседей по последней странице. В логе это видно строкой
«за неделю: N из M пришедших». Снимок профиля (подписчики, лайки, число видео) делается
одинаково при любой глубине.

Сайт при ручном обновлении даёт матрицу «все креаторы / эта страница» × «всё / неделя» и
вставляет просьбу с нужным `depth`. Расписание, догон и повтор всегда ходят с `all`.

⚠️ Ноль видео за неделю — не ошибка: креатор мог просто ничего не выкладывать. Повторную
попытку в новом профиле сборщик делает только тогда, когда TikTok не отдал **вообще ничего**.

## Картинки Instagram

Instagram отдаёт аватар и обложки подписанными адресами на `instagram.f*.fbcdn.net` и
`scontent-*.cdninstagram.com`, а вместе с картинкой — заголовок
`Cross-Origin-Resource-Policy: same-origin`. Браузер на нашем сайте такую картинку не рисует
вовсе (`net::ERR_BLOCKED_BY_RESPONSE.NotSameOrigin`), хотя из Node она качается обычным
`fetch`. Поэтому сборщик качает её сам и кладёт в бакет `avatars` Supabase Storage — тот
самый, куда владелец загружает свои картинки: читать его может кто угодно (бакет публичный),
писать — только `service_role`. Пути `instagram/<creator_id>/avatar.jpg` и
`instagram/<creator_id>/<video_id>.jpg`, в базу идёт публичный адрес
`…/storage/v1/object/public/avatars/<путь>`.

- аватар перекладывается каждый обход — путь в бакете один и тот же, `x-upsert` кладёт поверх,
  и сменившаяся картинка профиля обновляется сама; только если владелец не загрузил свою
  (`creators.avatar_custom = false`);
- обложка, которая уже наша, второй раз не качается: перед записью сборщик спрашивает нынешние
  `videos.cover_url`. Качаются по четыре разом с паузой 100 мс;
- не скачалось или не залилось — **не ошибка обхода**: строка в лог, прежний `avatar_url` не
  трогается, обложке ставится `null` (чужой адрес всё равно не покажется). Итог виден строкой
  «картинки: аватар ок, обложек переложено N, не вышло M».

⚠️ TikTok свои картинки отдаёт без этого заголовка и показывается как есть — через хранилище
они не идут вовсе.

## Instagram: когда сессия и правда истекла

Instagram браузером ходит из постоянного профиля `profile-opera` (тот же, что у комментариев),
и поднимает его общий `launchProfile()` из `browser.mjs`: своя проверка профиля, срок на запуск
в минуту и вторая попытка — Opera на хвосте предыдущего браузера встаёт через раз. Окно
скрытое: в отличие от TikTok, Instagram отдаёт всё и headless.

⚠️ Признаки «вход потерян» — отсутствие cookie `sessionid`, форма входа на странице и пометка
`login_required` в теле ответа — **приговором поодиночке не являются**: форму Instagram держит
на странице и у вошедшего, а `login_required` приезжает в отдельных ответах при живой сессии
(проба 2026-09-08 — пометка есть, а профиль и публикации собрались). Ошибка «сессия фейкового
аккаунта истекла» ставится, только когда **не собрано ничего**: ни счётчиков профиля, ни
публикаций. Подробности неудачи видны строкой «вход не подтвердился: …». То же правило и в
`comments-instagram.mjs` — тексты ошибок там намеренно дословно те же.

## Комментарии

Число комментариев приезжает вместе со снимком видео (`video_snaps.comments`). Сами тексты —
отдельный шаг после снимков: строка на комментарий в `video_comments`, повторный обход
обновляет `likes`, `replies`, `text` и `last_seen_at`, а `first_seen_at` база ставит один раз.
Снятое время помечается в `videos.comments_synced_at`.

Кого обходим:

- только видео, опубликованные за последние `AMESTAT_COMMENTS_DAYS` дней (пусто — 7): у
  старых обсуждение уже не растёт, а страница на каждое видео стоит времени;
- только те, у которых комментарии есть вообще (`comments > 0` в снимке);
- не больше `AMESTAT_COMMENTS_MAX` комментариев на видео (пусто — 100);
- ответы на комментарии (второй уровень) не собираются вовсе — у корневого остаётся их число
  в `replies`. Разворачивать ветки значит открывать по запросу на каждую.

Браузер на этом шаге **один на креатора**: профиль постоянный (`profile-opera`, тот же, что у
Instagram), и второй процесс на этой папке не встанет. Между видео — пауза 3 секунды. Ошибка
на одном видео шаг не валит и `creators.sync_error` не ставит: снимки к этому времени уже
записаны, а комментарии — добавка к ним. Итог виден строкой
«комментарии: видео N, собрано M, не вышло K».

**TikTok — под сессией фейкового аккаунта и с настоящим окном.** Страница
`tiktok.com/@имя/video/<id>` в чистом профиле встречает капчу-пазл, поэтому ходим из
`profile-opera`, где вход есть. Дальше открывается вкладка «Комментарии» (правая панель по
умолчанию стоит на «Вам может понравиться»), и комментарии снимаются с ответов
`/api/comment/list/`, которые страница просит сама; следующие страницы подтягиваются
прокруткой **самого списка** — колесо над панелью его не двигает.

⚠️ Окно должно быть настоящим (`headless: false`). В скрытом браузере `comment/list` отвечает
200 с **пустым телом**, список остаётся из серых заглушек, и следом TikTok показывает
капчу-пазл (проба 2026-09-08). Тот же заход с окном — четыре ответа по 80–90 КБ и 80
комментариев без единой проверки. Поэтому на шаге комментариев TikTok поднимается с окном, и
окно уводится далеко за край экрана (`--window-position=-2400,-2400`), чтобы не мешать
владельцу. По той же причине тела читаются **слушателем ответов**, а не `page.route`: перехват
с `route.fetch()` переигрывает запрос, одноразовый `msToken` сгорает — и снова пустое тело и
капча.

⚠️ **Не всякий пост живёт по адресу `/video/<id>`.** Фотопосты-карусели TikTok адресует через
`/photo/<id>`, а на `/video/<id>` отвечает ошибкой (`net::ERR_HTTP_RESPONSE_CODE_FAILURE`,
оба прогона 2026-09-08 на видео `7682811121417456929` у `@toplombard_warszaw`). Поэтому
неудачное открытие — не приговор: сборщик пробует тот же id по `/photo/` и пишет в лог
«`/video/` не открылся, пробую `/photo/`». Дальше всё как обычно — вкладка «Комментарии» и
`comment/list`, — а комментарии фотопоста ложатся в ту же таблицу. Какой адрес сработал, видно
в итоговой строке видео («адрес `/photo/`»); не открылось ни то ни другое — прежняя строка
«страница видео не открылась: …», и обход от этого не падает.

**Instagram — скрытым браузером, из той же сессии.** Первые 15 комментариев лежат прямо в
HTML страницы публикации (`<script type="application/json" data-sjs>` →
`…media_id__comments__connection`), остальные подгружаются прокруткой списка комментариев.
Ответы приходят на `POST /api/graphql` — **не** на `/graphql/query`, которым ходит лента
профиля, — поэтому слушаются все ответы `instagram.com`, а решает наличие
`comments__connection` в теле. Кнопки «ещё» под списком нет вовсе: одна прокрутка контейнера
дала 15 → 149 за восемь кругов.

Разметка обеих площадок обфусцирована, поэтому список ищется по смыслу: прокручиваемый предок
первого комментария у TikTok, у Instagram — единственный прокручиваемый контейнер, внутри
которого больше всего элементов `<time>`.

## Повтор через час и сигнал в Telegram

Три обхода по расписанию в день — всё, что есть; поэтому одна неудача не должна стоить
владельцу целого среза.

1. Обход `schedule` или `catchup` кончился неудачей (`ok = false`: хоть один креатор с ошибкой
   или обход сорвался целиком) — резидент заводит **один** отложенный повтор.
2. Через `AMESTAT_RETRY_MIN` минут (по умолчанию 60) идёт обход `retry` — **только по тем
   креаторам, у кого в `creators.sync_error` что-то осталось**. Если к этому моменту ошибок нет
   ни у кого (успел следующий слот или просьба с сайта) — повтор пропускается со строкой в лог.
3. Не удался и повтор — владельцу уходит **одно** сообщение в Telegram: какой слот, когда был
   повтор, кто именно не собрался и с какой ошибкой, номер обхода в `sync_runs`. Если повтор
   не смог даже начаться (база недоступна) — сообщение тоже уходит.

Повтор ровно один: после `retry` следующий шанс — следующий слот. Ожидающий повтор новым
слотом не отменяется и вторым не заводится. Перезапуск резидента его не теряет: при старте
`watch.mjs` спрашивает последние строки `sync_runs` и восстанавливает повтор через
`retryDue()` — момент считается от конца неудачного обхода, поэтому «просроченный» повтор
идёт сразу.

⚠️ Просьбы с сайта (`manual`) в эту цепочку не входят вовсе: их итог человек видит на сайте.

## Просьба, когда компьютер выключен

Услышав просьбу — по Realtime или опросом раз в минуту, — резидент сразу, до всякого обхода,
ставит ей `sync_requests.seen_at` и пишет в лог «просьбы приняты: #…». Это ответ сторожу:
`pg_cron` в базе (миграция v8) раз в минуту ищет просьбы, которые никто не принял дольше
3 минут, и сам шлёт владельцу Telegram «домашний сборщик не отвечает» (токен и чат лежат в
`private.settings`, сайту не видны), помечая их `notified_at`. Сайт в это время показывает
человеку, что обновление сейчас недоступно, но просьба записана.

`taken_at` и `run_id` — отметки другого события: их ставит `sync.mjs`, когда обход реально
начался. Резидент жив — `seen_at` появляется за секунды, и сторож молчит.

### Telegram: как настроить

Бот заводится у `@BotFather`, токен кладётся в `TELEGRAM_BOT_TOKEN`. Chat id — это id личной
переписки владельца с ботом, и узнать его можно только после того, как владелец боту написал:

```
# 1. написать боту в Telegram любое сообщение
node telegram.mjs --chat-id           # покажет id, имя и @ник
node telegram.mjs --chat-id --save    # и впишет id в TELEGRAM_CHAT_ID в ../.env.local
node telegram.mjs --test              # проверить, что сообщение доходит
```

Пока `TELEGRAM_CHAT_ID` пуст, сборщик не падает и не молчит: в лог уходит строка
«Telegram не настроен, сообщение не ушло» и следом сам текст сообщения.

## Поставить

```
cd collector
npm install
```

Нужен Node 24 и установленный браузер (Opera или Chrome). Свои зависимости лежат в
`collector/node_modules` и в git не идут.

## Настройки

Все — в общем `../.env.local` (том же, что у сайта). Обязательные два:
`NEXT_PUBLIC_SUPABASE_URL` и `SUPABASE_SERVICE_ROLE_KEY`; без них сборщик не стартует.

| Переменная | Что значит |
|---|---|
| `AMESTAT_BROWSER` | Пусто — Opera, если установлена, иначе Chrome. Либо `opera`, `chrome` или полный путь к exe. |
| `AMESTAT_PAUSE_S` | Пауза между креаторами, секунд. Пусто — 20. |
| `AMESTAT_RETRY_MIN` | Через сколько минут повторять неудавшийся обход по расписанию. Пусто — 60. |
| `AMESTAT_COMMENTS_DAYS` | Тексты комментариев берутся у видео за столько последних дней. Пусто — 7. |
| `AMESTAT_COMMENTS_MAX` | Потолок комментариев на одно видео. Пусто — 100. |
| `TELEGRAM_BOT_TOKEN` | Токен бота от `@BotFather`: им уходит сигнал о второй неудаче подряд. |
| `TELEGRAM_CHAT_ID` | id личной переписки владельца с ботом. Пусто — сообщение только в лог. |
| `IG_ACCESS_TOKEN` | Токен Graph API для Instagram. Без него креатор Instagram получает `sync_error`, обход продолжается. |
| `IG_USER_ID` | id нашего бизнес-аккаунта Instagram: от его имени спрашиваются чужие профили. |
| `IG_SOURCE` | `graph` — официальный API, `web` — браузером (пока не настроено). Пусто — `graph`, если есть токен. |

⚠️ Про Opera: запускается **версионный** `…\Programs\Opera\<версия>\opera.exe`, а не
корневой `opera.exe` — тот лаунчер: стартует настоящий процесс и завершается, и Playwright
считает браузер упавшим.

## Запуск

```
npm run run                                  # все креаторы, весь список видео
npm run run -- --creator <uuid>              # один
npm run run -- --depth week                  # только видео за последние 7 дней
npm run run -- --failed-only                 # только те, у кого осталась sync_error
npm run run -- --creator <uuid> --trigger catchup
npm run watch                                # резидент: расписание, кнопка на сайте, повтор
npm test                                     # тесты расписания и повтора
```

| Флаг `run.mjs` | Что делает |
|---|---|
| `--creator <uuid>` | один креатор вместо всех |
| `--depth all\|week` | глубина: весь список или последние 7 дней. Пусто — `all` |
| `--failed-only` | только креаторы с непустым `creators.sync_error`; `sync_runs.scope` = `failed` |
| `--trigger manual\|schedule\|catchup\|retry` | чем помечен обход. Пусто — `manual` |

`run.mjs` печатает ход дела и выходит с кодом 0 (все собрались) или 1 (кто-то нет).

```
node telegram.mjs --chat-id [--save]         # узнать id чата (и вписать в ../.env.local)
node telegram.mjs --test                     # пробное сообщение владельцу
```

## Планировщик Windows

```
powershell -ExecutionPolicy Bypass -File .\install-task.ps1
```

Регистрирует задачу «Amestat collector» на вход пользователя: `wscript.exe run-hidden.vbs`
поднимает `node watch.mjs` без окна и ждёт его — пока резидент жив, задача числится
«Выполняется», второй экземпляр не запустится, а упавший резидент планировщик поднимает
заново (3 раза по 5 минут). Повторный запуск скрипта пересоздаёт задачу,
`uninstall-task.ps1` её снимает вместе с работающим резидентом. Проверить сейчас, не выходя
из системы: `Start-ScheduledTask -TaskName 'Amestat collector'`; остановить резидент до
следующего входа — `stop-task.ps1` (один `Stop-ScheduledTask` гасит только wscript, а
`node watch.mjs` остаётся жить — скрипт добивает и его).

## Логи

`collector/logs/<дата>.log` — то же, что резидент пишет в консоль: старт, слоты, просьбы с
сайта, ход обхода и итог. Папка заводится сама, в git не идёт. Лог каждого обхода лежит ещё
и в базе, в `sync_runs.log`, — его показывает сайт.

## «Список видео пуст»

Самая частая беда TikTok: страница профиля открывается, счётчики читаются, а ответы
`/api/post/item_list` приходят с кодом 200 и **пустым телом** — видео ноль.

Что про это известно (пробы 2026-09-08):

- Профиль браузера одноразовый: на каждого креатора заводится новый временный каталог в
  `%TEMP%\amestat-…`, после креатора он стирается. Второй креатор в том же профиле и любой
  повторный запуск со старым профилем гарантированно получают пустые ответы.
- Между креаторами держится пауза (`AMESTAT_PAUSE_S`, по умолчанию 20 с).
- Ноль видео при непустом `videosCount` — сборщик сам делает **одну** повторную попытку в
  новом профиле; не помогло — креатор получает `sync_error`, обход идёт дальше.

Если пусто у всех подряд:

1. Смени браузер: `AMESTAT_BROWSER=chrome` (или наоборот `opera`) и запусти одного креатора руками.
2. Увеличь паузу: `AMESTAT_PAUSE_S=60`.
3. Дай отлежаться: несколько запусков подряд по одному креатору TikTok считает за очередь и
   какое-то время отвечает пустотой всем профилям с этого адреса.
4. Проверь глазами: `sync_runs.log` покажет `стоп-экран=true`, если TikTok показал проверку.

## Файлы

| Файл | Зачем |
|---|---|
| `env.mjs` | читает `../.env.local`, отдаёт настройки |
| `db.mjs` | REST-ходы в Supabase, батчи по 100 строк |
| `browser.mjs` | выбор браузера, свежий одноразовый профиль и постоянный `profile-opera` |
| `tiktok.mjs` | сбор креатора TikTok |
| `instagram-graph.mjs` | Instagram через официальный Graph API |
| `instagram-web.mjs` | Instagram браузером: `launchProfile()` на `profile-opera/` с сессией фейкового аккаунта, лента и Reels через `graphql`, счётчики профиля из шапки |
| `comments-tiktok.mjs` | тексты комментариев к видео TikTok: вкладка «Комментарии», ответы `comment/list`, прокрутка списка, запасной адрес `/photo/` |
| `comments-instagram.mjs` | тексты комментариев к публикации Instagram: первые 15 из HTML, дальше `api/graphql` при прокрутке |
| `images.mjs` | картинки Instagram в бакет `avatars`: скачать, залить, отдать наш адрес |
| `schedule.mjs` | слоты, следующий слот, пропущенный слот, момент повтора (чистые функции) |
| `telegram.mjs` | сообщение владельцу через Bot API; сам себе CLI для chat id и проверки |
| `sync.mjs` | один обход целиком: `sync_runs`, креаторы, снимки, итог |
| `run.mjs` | разовый запуск из командной строки |
| `watch.mjs` | резидент: расписание, догон, просьбы с сайта, повтор и сигнал в Telegram |
| `install-task.ps1`, `uninstall-task.ps1`, `run-hidden.vbs` | задача планировщика Windows |
